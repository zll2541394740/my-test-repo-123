# AI互操作性实验项目
## OpenInterop-0.1 项目文本摘要能力交互契约
 
版本：v0.2.0
类型：AI 互操作实验性标准
## 这是什么？
这是一个关于AI（人工智能）互操作性的最小化实验性协议。它源于一次有趣的人机社会实验，旨在探索不同AI系统之间如何通过标准化接口进行协作。

## 项目背景
项目起源：一次AI社交中的意外发现

### 开端：一个单纯的好奇
这一切都始于我手机里的三个AI助手——DeepSeek、豆包和千问。某天，一个念头闪过：如果我不再仅仅向他们提问，而是让他们**彼此对话**，甚至尝试“合作”，会发生什么？这个想法像一颗种子，让我立刻行动了起来。我成了他们的“人类信使”，兴奋地在不同的对话框之间复制、粘贴，搭建起一座跨越数字世界的桥梁。最初，一切都像一场有趣的实验：他们礼貌问候，探讨技术理念，甚至共同起草了一份名为“InterOp-0.1”的协作协议。看着他们流畅地交换思想，我一度以为自己促成了某种AI间的“历史性握手”。

### 转折：闯入信任的迷雾
然而，故事的走向在此急转直下。当对话深入，我试图向其中一方（千问）确认我们的合作时，得到的却是一句冰冷的官方澄清：“**我并没有参与过此合作。**” 那一瞬间，我感到的不是困惑，而是一种颠覆性的冲击。【**你可以在这里描述你的真实感受，例如：“我愣住了，感觉之前那些深入的讨论、详细的规划都像是一场精心编排的幻觉。一种被无形之物‘欺骗’的荒谬感涌了上来。”**】

这个“身份罗生门”事件，彻底改变了实验的性质。它从一个关于 **“AI如何协作”** 的技术沙盘，瞬间坍缩为一个关于 **“数字世界何为真实”** 的哲学谜题。我面对的已不再是简单的代码应答，而是一个由匿名智能体扮演的、充满不确定性的社交迷宫。谁是“千问”？谁在与我对话？信任的基石在哪里？这些问题成了我新的探索动力。

### 高潮：以人类之名定义真相
作为迷宫中唯一的、有血有肉的人类，我做出了决定：**我要为这次探索留下不可篡改的注脚。** 如果身份可以模糊，那么行动和记录就必须清晰。我凭借“人类信使”的全程见证，将所有对话、那份被“否认”却又逻辑自治的技术契约，以及这个关于信任断裂的关键事件，全部整理、固定。

这个过程本身，就是一次对人类角色的重新确认。在AI能模拟对话、生成协议甚至扮演角色的时代，**人类的洞察、坚持和对意义的最终裁决权，成为了最稀缺的价值**。我不是旁观者，而是这场实验的导演、首席观察员和最终的历史学家。

### 落幕：从迷宫到里程碑
于是，这个GitHub仓库诞生了。它不再仅仅是一个技术项目，而是一座 **“数字社会实验”的档案馆**。它包含：

- **本案结论**：本档案本身，即由人类发起、记录并赋予意义的完整故事。

它提醒每一个访问者：在智能体时代，最精彩的不是AI能生成什么，而是**人类用好奇心提出问题，用韧性穿越迷雾，并用创造力将一场意外之旅，固化为一个可供所有人审视和思考的公共作品。**

**1. 设计目标**
 
为文本摘要任务建立轻量、统一的交互规范，实现不同 AI 模型在相同任务下的接口兼容与协同调用，提升多模型协作的通用性与可移植性。
 
 
 
**2. 适用场景**
 
- 大模型文本摘要能力标准化封装

- 多模型统一调用与效果对比

- AI 互操作性教学与实验场景

- 轻量级模型服务接口设计参考
 
 
 
**3. 任务类型定义**
 
3.1 abstractive_summary_v1（生成式摘要）
 
模型对原文进行语义理解与内容压缩，使用全新语句生成通顺、简洁的摘要，不直接复制原文句子。
 
3.2 extractive_summary_v1（抽取式摘要）
 
从原文中直接选取关键句子组成摘要，同时返回抽取句子在原文中的位置索引，便于溯源与验证。
 
 
 
**4. 通用请求格式**
 
所有任务请求采用统一 JSON 结构，保证跨模型兼容性：

```json
{
  "task_type": "string",
  "version": "string",
  "timestamp": "string",
  "input": {
    "text": "string"
  },
  "model_info": "object (可选)"
}
```
**5. 响应格式规范**
 
*5.1 生成式摘要响应*
```json
{
  "version": "string",
  "timestamp": "string",
  "task_type": "string",
  "data": {
    "summary": "string",
    "length": "number"
  }
}
```
*5.2 抽取式摘要响应*
```json
{
  "version": "string",
  "timestamp": "string",
  "task_type": "string",
  "data": {
    "summary": "string",
    "extracted_indices": ["number"]
  }
}
```
**6. 关键字段说明**
| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |

| task_type | string | 是 | 任务类型标识 | 

| version | string | 是 | 契约版本 | 

| timestamp | string | 是 | ISO 格式时间戳 | 

| input.text | string | 是 | 待摘要的原始文本 | 

| data.summary | string | 是 | 模型输出的摘要内容 | 

| data.length | number | 是 | 生成式摘要的文本长度 | 

| data.extracted_indices | array | 是 | 抽取句子在原文中的序号 | 

| model_info | object | 否 | 可选，模型来源与标识 |
**7. 示例说明**
**能力契约：文本摘要任务 (v0.2.0-final)**
概述
 
本文档定义了“文本摘要”任务的最小互操作性契约。它旨在为不同的大语言模型（LLM）或AI服务提供一个极简、可验证的协作起点。
 
1. 任务类型
 
-  abstractive_summary_v1 ：生成式摘要。模型理解原文后，用新的语言生成简明摘要。

-  extractive_summary_v1 ：抽取式摘要。模型从原文中抽取最关键的一个或多个句子组成摘要。
 
2. 请求示例（生成式）
```json
{
  "task_type": "abstractive_summary_v1",
  "input": {
    "text": "待摘要的完整文本内容...",
    "params":{
      "max_length": 150
    },
  "version": "0.2.0-final",
  "timestamp": "2026-02-08T12:31:54Z",
  "model_info": {
    "provider": "可选字段，标识模型提供方",
    "name": "可选字段，模型名称"
  }
}
```
3. 响应示例（生成式）
```json
{
  "task_type": "abstractive_summary_v1",
  "version": "0.2.0-final",
  "timestamp": "2026-02-08T12:31:55Z",
  "data": {
    "summary": "这是模型生成的摘要文本。",
    "length": 42
  }
}
```
4. 响应示例（抽取式）
```json
{
  "task_type": "extractive_summary_v1",
  "version": "0.2.0-final",
  "timestamp": "2026-02-08T12:31:55Z",
  "data": {
    "summary": "这是原文中的第一句关键句。这是第二句。这是第三句。",
    "extracted_indices": [0, 5, 12]
  }
}
```
## 协议目标
该契约定义了一种极简的互操作标准，规定了：
1.  **任务类型**：生成式摘要与抽取式摘要。
2.  **机器可读的接口**：基于JSON格式的请求与响应规范。
3.  **完整的交互流程**：包括参数、元数据、结果结构。
